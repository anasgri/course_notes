Markdown Basic Syntax Guide

The core elements from the original Markdown design, with what to type and what you get.

Overview

Almost every Markdown application supports the basic syntax from the original Markdown design document. Processors differ in small ways, so each section notes the habits that work everywhere. The "Do" and "Don't" boxes show the most compatible choices.

Headings

Start a line with number signs (#). The count sets the level, from one to six.

Markdown
# Heading level 1
## Heading level 2
### Heading level 3
#### Heading level 4
##### Heading level 5
###### Heading level 6
Result

Heading level 1

Heading level 2

Heading level 3

Heading level 4

Heading level 5
Heading level 6

Alternate syntax

Underline the text with === for level 1 or --- for level 2.

Markdown
Heading level 1
===============

Heading level 2
---------------
Result

Heading level 1

Heading level 2

Best practices

✅ Do this

# Here's a heading

Blank lines sit before and after.

❌ Don't do this

#No space after the sign
Text right after a heading

Paragraphs

Separate paragraphs with a blank line.

Markdown
I really like using Markdown.

I think I'll use it to format
all of my documents.
Result

I really like using Markdown.

I think I'll use it to format all of my documents.

Don't indent paragraphs with spaces or tabs unless the paragraph is inside a list. Indenting can cause unexpected formatting.

Line breaks

End a line with two or more spaces, then press return, to get a <br>.

Markdown (· marks a trailing space)
This is the first line.··
And this is the second line.
Result

This is the first line.
And this is the second line.

Trailing spaces work nearly everywhere but are invisible in most editors, which is why some people dislike them. If your application allows HTML, ending the line with <br> is easier to see.

✅ Do this

First line, two spaces after.··
Next line.

First line with a tag.<br>
Next line.

❌ Don't do this

First line with a backslash.\
Next line.

First line with nothing after.
Next line.

A trailing backslash is CommonMark-only, and a bare return only works in a few lightweight markup languages.

Emphasis

Bold

Wrap text in two asterisks or two underscores. To bold part of a word, use asterisks with no spaces.

Markdown
I just love **bold text**.
I just love __bold text__.
Love**is**bold
Result

I just love bold text.
I just love bold text.
Loveisbold

Italic

Wrap text in one asterisk or one underscore. Again, use asterisks inside a word.

Markdown
Italicized text is the *cat's meow*.
Italicized text is the _cat's meow_.
A*cat*meow
Result

Italicized text is the cat's meow.
Italicized text is the cat's meow.
Acatmeow

Bold and italic

Use three asterisks or underscores, or nest one style inside the other.

Markdown
This text is ***really important***.
This text is ___really important___.
This text is __*really important*__.
This text is **_really important_**.
This is really***very***important text.
Result

This text is really important.
This text is really important.
This text is really important.
This text is really important.
This is reallyveryimportant text.

Processors disagree on underscores in the middle of a word, so use asterisks for mid-word emphasis: Love**is**bold, not Love__is__bold. The order of the em and strong tags may also vary between processors.

Blockquotes

Put > in front of a paragraph.

Markdown
> Dorothy followed her through
> many of the beautiful rooms
> in her castle.
Result

Dorothy followed her through many of the beautiful rooms in her castle.

Multiple paragraphs

Add a > on the blank line between paragraphs.

Markdown
> Dorothy followed her through
> many of the beautiful rooms.
>
> The Witch bade her clean the
> pots and kettles.
Result

Dorothy followed her through many of the beautiful rooms.

The Witch bade her clean the pots and kettles.

Nested

Use >> for the inner quote.

Markdown
> Dorothy followed her through
> many of the beautiful rooms.
>
>> The Witch bade her clean the
>> pots and kettles.
Result

Dorothy followed her through many of the beautiful rooms.

The Witch bade her clean the pots and kettles.

With other elements

Quotes can hold headings, lists, and emphasis. Not every element works in every processor, so experiment.

Markdown
> #### The quarterly results look great!
>
> - Revenue was off the chart.
> - Profits were higher than ever.
>
> *Everything* is going according to **plan**.
Result

The quarterly results look great!

  • Revenue was off the chart.
  • Profits were higher than ever.

Everything is going according to plan.

Leave blank lines before and after a blockquote for best compatibility.

Lists

Ordered lists

Number each item followed by a period. The numbers needn't be in sequence, but start with 1. Indent items to nest them.

Markdown
1. First item
2. Second item
3. Third item
    1. Indented item
    2. Indented item
4. Fourth item
Result
  1. First item
  2. Second item
  3. Third item
    1. Indented item
    2. Indented item
  4. Fourth item

Writing 1. on every line, or 1. 8. 3. 5., gives the same rendered numbering. Use periods only: 1) is supported by CommonMark but not everywhere.

Unordered lists

Start items with -, *, or +. Indent to nest.

Markdown
- First item
- Second item
- Third item
    - Indented item
    - Indented item
- Fourth item
Result
  • First item
  • Second item
  • Third item
    • Indented item
    • Indented item
  • Fourth item

✅ Do this

- First item
- Second item
- Third item

❌ Don't do this

+ First item
* Second item
- Third item

Pick one delimiter per list, since mixing them behaves differently across applications.

Starting an item with a number

Escape the period with a backslash so it isn't read as an ordered list.

Markdown
- 1968\. A great year!
- I think 1969 was second best.
Result
  • 1968. A great year!
  • I think 1969 was second best.

Adding elements inside lists

Indent the extra element four spaces or one tab to keep the list continuous.

Paragraph in a list
* This is the first list item.
* Here's the second list item.

    I need another paragraph below it.

* And here's the third list item.
Blockquote in a list
* This is the first list item.
* Here's the second list item.

    > A blockquote would look great
    > below the second list item.

* And here's the third list item.
Code block in a list (eight spaces)
1. Open the file.
2. Find this code on line 21:

        <html>
          <head>
            <title>Test</title>
          </head>

3. Update the title.
Image in a list
1. Open the file with the mascot.
2. Marvel at its beauty.

    ![Tux, the Linux mascot](tux.png)

3. Close the file.
If a list doesn't look right, check that nested elements are indented four spaces or one tab (eight spaces or two tabs for code blocks).

Code

Wrap a word or phrase in backticks to mark it as code.

Markdown
At the command prompt, type `nano`.
Result

At the command prompt, type nano.

Backticks inside code

Use double backticks around text that contains a backtick.

Markdown
``Use `code` in your Markdown file.``
Result

Use `code` in your Markdown file.

Code blocks

Indent every line of the block by at least four spaces or one tab.

Markdown
    <html>
      <head>
      </head>
    </html>
Result
<html>
  <head>
  </head>
</html>
To make code blocks without indenting, use fenced code blocks from the extended syntax.

Horizontal rules

Put three or more asterisks, dashes, or underscores on a line by themselves. All three produce the same line.

Markdown
***

---

_________________
Result

✅ Do this

A blank line before...

---

...and after the rule.

❌ Don't do this

Without a blank line,
---
this turns into a heading.

Links

Put the link text in brackets and the URL right after it in parentheses.

Markdown
My favorite search engine is
[Duck Duck Go](https://duckduckgo.com).
Result

My favorite search engine is Duck Duck Go.

Adding a title

A quoted title after the URL shows as a tooltip on hover.

Markdown
[Duck Duck Go](https://duckduckgo.com "The best search engine for privacy")
Result

Duck Duck Go

URLs and email addresses

Wrap a URL or email address in angle brackets to make it clickable.

Markdown
<https://www.markdownguide.org>
<fake@example.com>
Result

https://www.markdownguide.org
fake@example.com

Formatting links

Put emphasis markers outside the brackets and parentheses. To make link text look like code, put backticks inside the brackets.

Markdown
I love supporting the **[EFF](https://eff.org)**.
This is the *[Markdown Guide](https://www.markdownguide.org)*.
See the section on [`code`](#code).
Result

I love supporting the EFF.
This is the Markdown Guide.
See the section on code.

Reference-style links

Keep long URLs out of your paragraph. The inline part uses two sets of brackets: the visible text, then a label. The definition lives elsewhere in the file, such as under the paragraph or at the end.

Markdown
It was a [hobbit-hole][1], and
that means comfort.

[1]: <https://en.wikipedia.org/wiki/Hobbit#Lifestyle> "Hobbit lifestyles"
Result

It was a hobbit-hole, and that means comfort.

  • Labels aren't case sensitive and can contain letters, numbers, spaces, or punctuation.
  • A space between the two sets of brackets is allowed: [hobbit-hole] [1].
  • The definition is [label]: URL "Title". The URL may be in angle brackets, and the title may use double quotes, single quotes, or parentheses.

Best practices

Encode spaces in URLs as %20 and parentheses as %28 and %29. Alternatively, use an HTML <a> tag if your application supports HTML.

✅ Do this

[link](https://www.example.com/my%20great%20page)

[a novel](https://en.wikipedia.org/wiki/The_Milagro_Beanfield_War_%28novel%29)

❌ Don't do this

[link](https://www.example.com/my great page)

[a novel](https://en.wikipedia.org/wiki/The_Milagro_Beanfield_War_(novel))

Images

Write an exclamation mark, alt text in brackets, then the path or URL in parentheses. A quoted title is optional. 

![The San Juan Mountains are beautiful](/assets/images/san-juan-mountains.jpg "San Juan Mountains")

Linking an image

Wrap the whole image in brackets and add the link target in parentheses. 

[![An old rock in the desert](/assets/images/shiprock.jpg "Shiprock, New Mexico")](https://www.flickr.com/photos/beaurogers/31833779864)
Resizing and captions aren't part of basic syntax. Use HTML or an extended feature for those.

Escaping characters

Put a backslash before a character to show it literally instead of as formatting.

Markdown
\* Without the backslash, this
would be a bullet in a list.
Result

* Without the backslash, this would be a bullet in a list.

Characters you can escape

Character Name Character Name
\ backslash ( ) parentheses
` backtick # pound sign
* asterisk + plus sign
_ underscore - minus sign (hyphen)
{ } curly braces . dot
[ ] brackets ! exclamation mark
< > angle brackets | pipe

HTML

Many Markdown applications accept raw HTML, which is handy for things Markdown can't express, like text color or image width.

Markdown
This **word** is bold. This <em>word</em> is italic.
Result

This word is bold. This word is italic.

  • Some applications block HTML for security, or allow only a subset of tags. Check the documentation.
  • Separate block-level elements (<div>, <table>, <pre>, <p>) from surrounding content with blank lines, and don't indent their tags.
  • Markdown syntax doesn't work inside block-level HTML tags: <p>italic and **bold**</p> won't format.
