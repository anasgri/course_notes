JavaScript testing

One way to automatically test the program is to use end-to-end (browser) test.

It opens a real browser, acts like a user, and checks that the app behaves correctly.

Lets look at the code below


it('accepts the customer name', () => {
  const name = 'Hungry Person';

  browser.url('/');
  browser.setValue('#name', name);
  browser.click('#submit-order');
  browser.url('/');

  assert.include(browser.getText('#deliver-to'), name);
});

The overall structure

it(description, function) defines one test. The text is a human-readable description of what should happen: “it accepts the customer name”. If the test fails, this is the label you’ll see in the output. The function holds the actual steps. 


    it('accepts the customer name', () => {
  // ...test body...
});

The three phases of a test

Almost every test follows the same pattern: Arrange, Act, Assert.

Arrange (set up the data)

const name = 'Hungry Person';

This just creates the value the test will use, so it can be reused later. This is to mimic the user, that would provide their name

Act (do what a user would do)


browser.url('/');                    // open the home page
browser.setValue('#name', name);     // type "Hungry Person" into the element with id="name"
browser.click('#submit-order');      // click the button with id="submit-order"
browser.url('/');                    // go back to the home page

The #name and #submit-order are CSS selectors. The # means “find the element with this id”. So the test is looking for something like <input id="name"> and <button id="submit-order"< in your HTML.

The browser object comes from a tool like WebdriverIO, which controls a real browser. 


assert.include(browser.getText('#deliver-to'), name);

This reads the text from the element with id deliver-to and checks that it includes “Hungry Person”. If it does, the test passes. If not, it fails.

  • 3. The test needs to reach your HTML

    browser.url('/') opens the base URL, so the HTML has to be served at that address. You have two options:

    Option A: Use file:// (simplest for learning, no server)

    In wdio.conf.js, set baseUrl to the full path of your HTML file's folder:

    baseUrl: 'file:///C:/Users/YourName/project/',

    Use forward slashes, and replace the path with your real one. Then browser.url('index.html') opens your file. Note that '/' would show a folder listing instead, so use the filename.

    Option B: Run a small local server

    Install one with:

    npm install --save-dev http-server

    Add a script to package.json:

    "scripts": {
  "start": "http-server -p 3000",
  "test": "wdio run wdio.conf.js"
}

    Then run this in one terminal:

    npm start

    Set baseUrl: 'http://localhost:3000' in wdio.conf.js, and browser.url('/') will load your index.html. This matches the setup used for real apps, so I'd recommend it.
